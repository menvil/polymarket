# Анализ калибровки толпы — Crowd Calibration Analysis

Скрипт `scripts/analyze-crowd-calibration.ts` измеряет, насколько точно рыночные цены (mid-price
ордербука) предсказывают реальный исход 5- и 15-минутных бинарных рынков BTC Up/Down на Polymarket.

---

## Зачем это нужно

Polymarket 5-min рынки: каждый рынок — это ставка «цена BTC на следующие 5 минут вырастет (UP)
или упадёт (DOWN) относительно страйка». Ордербук формирует цену UP-токена (0–100¢). Если толпа
хорошо откалибрована, цена 70¢ должна означать, что рынок резолвится UP в 70% случаев.

**Калибровка** показывает отклонение:
- `crowd_prob` = mid-price UP-токена (в центах → [0, 1])
- `real_prob` = UP-исходов / всего рынков в бакете
- `bias` = crowd − real (>0 = толпа завышает вероятность UP)
- `edge` = real − crowd (>0 = выгодно покупать UP, толпа недооценивает)

**Delta** = chainlink_price − strike_price ($). Грубо: насколько BTC уже выше/ниже страйка.

**Tau** = секунд до экспирации в момент наблюдения.

### `--token` и ордербуки

- `up` — использует bid/ask UP-токена → mid = (upBid + upAsk) / 2
- `down` — использует down-сторону: mid = 100 − (downBid + downAsk) / 2
- `both` — усредняет обе стороны. Позволяет сравнить «по UP-книге» vs «по DOWN-книге» и найти
  асимметрию в ликвидности

## Как читать ячейки

Во всех таблицах ячейка имеет вид:

```
real%(bias) n=рынков
```

Например: **`34%(+2) n=338`**
- `34%` — реальная частота UP-исходов в этом бакете (338 уникальных рынков)
- `+2` — bias = crowd − real: толпа ставила в среднем на 2% выше, чем реально сбылось
- `n=338` — количество уникальных рынков (дедуплицировано по slug)

Ещё пример: **`100%(-14) n=5`**
- 5 рынков, все резолвились UP
- crowd ставил в среднем 114¢ (т.е. ~86¢ после нормализации) — недооценка -14%

### Цветовое кодирование (bias)

| Цвет | Значение |
|---|---|
| **жирный зелёный** | edge ≥ 10% — сильная недооценка UP (выгодно покупать) |
| желтый | edge 5–10% |
| без цвета | edge < 5% (близко к нейтрали) |
| тёмный | bias 5–10% (лёгкая переоценка) |
| **тёмный красный** | bias ≥ 10% — сильная переоценка, UP дороже реала |

Классическая двумерная таблица. Строки = delta ($), столбцы = tau (сек). Каждая ячейка —
агрегация по всем crowd-ценам.

**Пример вывода:**
```

──────────────────────────────────────────────────────────────
+$25    76%(-6) n=38  79%(-5) n=39  81%(-4) n=41  82%(-5) n=40
 +$0    48%(+3) n=159 49%(+2) n=201 49%(+1) n=220 50%(+1) n=198
-$25     3%(+3) n=250  5%(+4) n=250  6%(+3) n=245  8%(+3) n=230
-$50     5%(+2) n=42  11%(+7) n=43  12%(+8) n=40  17%(+6) n=38
```

**Что искать:**
- `+$0` (BTC точно на страйке): crowd ~50¢, реал ~49–50% → отличная калибровка
- `+$25` (BTC на $25 выше страйка): crowd ~80¢, реал ~76–82% → лёгкая переоценка
- `-$25` (BTC на $25 ниже страйка): crowd ~5¢, реал ~3–8% → crowd завышает при коротком tau
- Большой отрицательный bias при низком tau = momentum переоценка

- Симметрия/асимметрия: сравните `--token up` vs `--token down` — если картина разная, в одной

## Технические детали

### Формат снапшотов

Скрипт читает `.jsonl.gz` файлы из директорий снапшотов. Каждая строка — JSON-объект с полями
ордербука, Chainlink-ценой, метаданными рынка.

**Два формата:**
1. Старый (2026-03-xx): `eventMetadata.priceToBeat` содержит страйк напрямую
2. Новый (2026-04-xx): `priceToBeat` отсутствует или `null` — страйк вычисляется как ближайшая по
   времени Chainlink-цена к `startTime` рынка

### Дедупликация рынков

Каждый рынок (slug) считается не более одного раза в бакете. При агрегации нескольких tau-окон
используется `mergeBuckets()` с проверкой slug → корректный подсчёт уникальных рынков.

### 3D-структура данных

Скрипт строит три карты:
- `deltaBuckets` — ключ `"delta:tau"` → Variants A, B, TOP, CURVE
- `crowdTauBuckets` — ключ `"duration:crowd5:tau"` → Variant 2
- `tripleMap` — ключ `"delta:tau:crowd10"` → Variants 1, 3, 4

Crowd-бакеты по 10¢ (не 5¢) снижают разрежённость в 3D-пространстве
(17 delta × 11 tau × 9 crowd ≈ 1683 теоретических ячейки).
