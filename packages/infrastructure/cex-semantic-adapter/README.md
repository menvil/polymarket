# @polymarket/cex-semantic-adapter

Semantic-граница CEX-контура: raw-наблюдения CCXT → canonical
`Orderbook<AssetPrice>` и ApplicationEvents.

## Место в контуре

```text
                    ExternalMessageBus
                   ↙                  ↘
      ExternalMessageRecorder      CexSemanticAdapter
                ↓                          ↓
              JSONL              Orderbook<AssetPrice>
                                           ↓
                                    ApplicationEvent
                                           ↓
                                       IEventBus
```

Адаптер — **второй независимый потребитель** того же raw-bus, что и
recorder. Он не владеет шиной, не знает про `CexSource`, `DataCollector` и
CCXT, и его отказ не мешает записи сырых данных.

## Почему адаптер не видит живой CCXT-инстанс

Вся входная информация приходит сообщением. Ни `watchOrderBook`, ни
REST-догрузка market info отсюда не вызываются: иначе live-путь и будущий
replay расходились бы — воспроизведённое сообщение не имеет за собой живой
биржи. Это свойство проверяется тестом на записанном архиве
(`CexSemanticAdapter.replay-parity.test.ts`).

## Одна каноническая модель стакана

Второй модели стакана под биржу не существует. Отличие ровно одно —
ценовой домен:

```text
рынок предсказаний → Orderbook<OutcomePrice>
биржа              → Orderbook<AssetPrice>
```

Оба проходят через generic `BOOK_DEPTH` / `BOOK_UPDATED` / `TRADE_RECEIVED`
без приведений типов.

## Идентичность

| Поле           | Значение                       | Почему так |
| -------------- | ------------------------------ | ---------- |
| `venueId`      | `BINANCE`, `OKX`, …            | `exchange.id` ccxt в верхнем регистре; таблицы соответствий нет — новая биржа работает без правок кода |
| `marketId`     | `undefined`                    | у биржи рынок не существует отдельно от инструмента; дублировать символ значило бы выдумать сущность |
| `instrumentId` | `spot:BTC/USDT`, `swap:BTC/USDT:USDT` | тип рынка входит в идентичность, потому что source-контракт не гарантирует, что vendor проставит суффикс расчётной валюты |

Vendor-символ сохраняется дословно: регистр, разделители, `:USDT`, дата
экспирации. Любая нормализация схлопывала бы разные контракты в один
инструмент.

## Стакан приходит полным снапшотом

`CexSource` публикует JSON-снапшот unified-стакана CCXT (усечённый до
глубины подписки), а не дельту. Поэтому реконструкции состояния книги здесь
нет: каждое наблюдение отображается независимо и целиком, второго кэша
книги адаптер не держит — только отпечаток верхушки и semantic-версию.

Отображение атомарно: один непригодный уровень отменяет **всё** наблюдение.
Книги «на 95 уровней из 96» не бывает — она выглядела бы исправной и молча
искажала бы глубину.

| Состояние книги | Поведение |
| --------------- | --------- |
| односторонняя   | публикуется; отсутствующая сторона в `TopOfBook` — `undefined` |
| пустая          | публикуется честно |
| скрещенная (`ask < bid`) | отвергается; цены не правятся, стороны не меняются местами |
| уровень с нулевым объёмом | сохраняется: source-контракт не объявляет такие строки удаляемым шумом |

## Семантика публикации

| Событие          | Когда публикуется |
| ---------------- | ----------------- |
| `BOOK_DEPTH`     | на каждое принятое наблюдение стакана |
| `BOOK_UPDATED`   | только когда верхушка действительно изменилась |
| `TRADE_RECEIVED` | на каждую принятую публичную сделку |

`sequenceNumber` у `BOOK_UPDATED` — счётчик, локальный для пары
`venueId + instrumentId`, растущий только после успешно принятого
наблюдения. Глобальная последовательность шины для этого непригодна: в ней
перемешаны другие биржи, символы и сообщения Polymarket, поэтому у одного
инструмента она имеет естественные «дыры», неотличимые от потерь.
`orderBook.nonce` тоже не используется — его отдают не все биржи (замер:
binance/okx/cryptocom да, bybit/coinbase/kraken нет), а его монотонность
через reconnect exchange-specific.

## Сделки: ничего не выдумывается

- **`venueTradeId`** берётся из unified-поля `id` как есть. Нет id → поле
  остаётся пустым. Ключ из времени, символа или хеша полей ЗАПРЕЩЁН: он
  молча склеил бы разные сделки. Замер на архиве (1 128 052 сделки,
  6 бирж): `id` есть у 100% наблюдений.
- **Объём** — только `amount`. `cost` объёмом не является, и
  `cost / price` не вычисляется. Нет `amount` → сделка пропускается,
  `Quantity(0)` не подставляется.
- **Сторона** переносится как есть (`buy` → `BUY`). Инверсии «по
  maker/taker» нет. Нет стороны → сделка пропускается.
- **Время**: vendor-время, если биржа его прислала; иначе время получения
  наблюдения — и это видно счётчиком `tradesMissingVenueTimestamp`.

### Дедупликация

`newUpdates: true` источника гарантирует «только новые сделки» в пределах
сессии, но не переживает пересоздание инстанса. Замер на записанном архиве
нашёл 525 повторов (cryptocom 517, coinbase 8) — побайтно идентичных, с тем
же стабильным venue-id; дистанция повтора: медиана 47, p95 50, максимум 74.
Поэтому повтор отсекается **ограниченным** окном по
`venueId + instrumentId + venueTradeId` (ёмкость 512 — семикратный запас).
Сделки без id в дедуп не попадают вовсе: без настоящего идентификатора
отличить повтор от двух одинаковых сделок невозможно.

## Точность

Unified-контракт CCXT отдаёт цены и объёмы как JS `number` — точность
зафиксирована **до** этого адаптера, внутри библиотеки. Адаптер её не
восстанавливает и не ухудшает: значение уходит в фабрику VO как есть, а
`Decimal` строится по кратчайшему round-trip-представлению числа
(`new Decimal(79233.99)` === `new Decimal('79233.99')`). Если vendor прислал
строку — она передаётся строкой, потому что строка точнее своего числового
представления. `Number()` / `parseFloat()` / `toNumber()` к финансовым
значениям в пакете не применяются нигде.

## Чего адаптер не делает

- не агрегирует площадки между собой — «лучшей глобальной книги» здесь нет;
- не считает индикаторы (imbalance, OFI, микроцена, VWAP, базис);
- не выводит `REFERENCE_PRICE_UPDATED` из середины книги или ленты — это
  производная проекция, а не наблюдение;
- не мутирует raw-payload (проверяется регрессией);
- `close()` снимает только свои подписки и **не** закрывает raw-bus.

## Использование

```typescript
import { CexSemanticAdapter } from '@polymarket/cex-semantic-adapter';

const adapter = new CexSemanticAdapter({
  bus,               // общий raw ExternalMessageBus контура
  eventBus,          // Application EventBus (создаёт composition root)
  metadataGenerator, // тот же canonical генератор, что у source-ов
  logger,
});

adapter.start();
// ...
adapter.close(); // подписки сняты, состояние освобождено, шина цела
```

## Диагностика

`getStats()` отдаёт read-only счётчики: `rawMessagesSeen`,
`orderBooksReceived` / `orderBooksPublished` / `invalidOrderBooks` /
`crossedOrderBooks`, `bookUpdatedPublished`, `tradesReceived` /
`tradesPublished` / `invalidTrades`, `tradesMissingId` /
`tradesMissingAmount` / `tradesMissingSide` / `tradesMissingVenueTimestamp`,
`duplicateTrades`, `invalidIdentities`, `semanticPublishFailures`,
`activeInstrumentStates`.

## Границы памяти

Состояние ограничено: на инструмент хранятся только semantic-версия,
отпечаток верхушки и окно из 512 идентификаторов сделок. Освобождение —
явное: `forgetInstrument(venueId, instrumentId)`, `forgetVenue(venueId)`,
`close()`. Адаптер специально не подписан на события жизненного цикла
сбора: это сделало бы semantic-слой collection-specific, а он обязан
одинаково работать и для live, и для replay.

## Live-верификация

```bash
npm run build
npx tsx scripts/verify-cex-semantic-live.mts
```

Скрипт поднимает production-фабрику контура (`createDataCollector`),
подключает адаптер вторым потребителем того же bus и печатает
per-venue свидетельства: счётчики raw/semantic, паритет лучших цен
raw ↔ canonical, паритет полей сделок и изоляцию площадок.
