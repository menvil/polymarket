# Уроки работы с площадкой Polymarket

Знания, добытые отладкой legacy `@polymarket/exchange` (17 683 строки). Сам
пакет **удалён** как устаревшая реализация, но эти факты о площадке от неё не
зависят — они понадобятся любому торговому контуру поверх canonical event
pipeline.

> Документ извлечён ПЕРЕД удалением кода. Проверить каждый пункт заново стоит
> часов отладки против минут чтения. Сам код доступен в истории git до
> коммита удаления.

## Подпись запросов: порядок операций критичен

```text
1. собрать тело запроса
2. добавить в тело EIP-712 подпись
3. ТОЛЬКО ПОСЛЕ ЭТОГО считать L2-заголовки
```

L2-заголовки считаются по **финальному** телу. Поменять шаги местами — подпись
не сойдётся, а сообщение об ошибке площадки не подскажет почему.

**Подписывается только путь, без query-параметров.** Официальный клиент
Polymarket делает именно так; включение query ломает проверку.

**Timestamp в СЕКУНДАХ, не миллисекундах:**

```typescript
const timestamp = Math.floor(Date.now() / 1000).toString();
const message = timestamp + method + requestPath + body;   // HMAC-SHA256
```

Для GET и DELETE тело в подписи — пустая строка.

## Семантика эндпоинтов: четыре похожих названия, четыре разных смысла

Это место, где легче всего построить неверную модель исполнения:

| эндпоинт | что возвращает |
| --- | --- |
| `TradesRestClient` | **публичные рыночные** сделки — не наши |
| `UserTradesRestClient` | **наши исполнения** (аутентифицированные) |
| `PositionsRestClient` | **исполненные** позиции — не открытые ордера |
| `OrderRestClient.getTrades` | **ОРДЕРА**, а не отдельные сделки |

Последняя строка — ловушка в названии метода.

## Gamma API адресует рынки по `slug`, не по `conditionId`

```text
GET /markets/{slug}          ← правильно
GET /markets/{conditionId}   ← HTTP 422 "id is invalid"
```

422 здесь — **ожидаемый** ответ, а не сбой. Legacy-клиент на нём возвращал
безопасные значения по умолчанию, а не падал.

## Ошибка маппинга ≠ «запись не наша»

`UserTrades` возвращает **только наши** записи. Поэтому если разбор записи не
удался, это **баг нашего маппинга или schema drift**, а не признак чужой
сделки. Молча пропускать такие записи нельзя — потеряется собственное
исполнение.

## Крипто-рынки: подписываться на ОБА потока

```text
resolutionSource содержит chain.link
  → подписка на crypto_prices И crypto_prices_chainlink
```

Резолвится рынок по Chainlink, но Binance-цена нужна для анализа расхождения.
Записывать оба с полем источника. Это же решение независимо подтвердилось в
V2-коллекторе, где оба потока пишутся в датасет рынка.

## Ретраи REST

```text
4xx           → НЕ повторять (постоянный сбой)
остальное     → экспоненциальный backoff: retryDelay * 2^attempt
```

Различие 4xx и 5xx — то, чего сейчас **нет** в V2-контуре: финализатор
ретраит Gamma однородно раз в 30 с до часа, на постоянном 4xx это ~120 лишних
вызовов на рынок.

## Классификатор ошибок площадки

Отдельный слой (`ErrorClassifier`, 417 строк) с ценными свойствами, которые
стоит воспроизвести, а не изобретать:

- **идемпотентность по ссылке**: `classify(classify(x)) === classify(x)`;
- **LRU-кэш** с ограничением (1000 записей) — классификация по тексту ошибки
  дорога, а ошибки повторяются;
- **ключ = тип + первые 100 символов сообщения**;
- **двойное кэширование при смене типа**: и входной, и результирующий ключ
  ссылаются на один объект;
- **без TTL** — кэш живёт сессию.

## Что НЕ проверялось

Исполнение ордеров целиком: построение ордера, tick size, округление,
post-only, отмена, reconciliation позиций. В legacy-пакете этот код есть, но
он не был предметом ни одного из аудитов этой сессии — только беглый просмотр
маркеров. Перед написанием нового execution-слоя стоит перечитать
`rest/auth/PolymarketOrderBuilder.ts` и `rest/clients/PolymarketOrderRestClient.ts`
в истории git.
