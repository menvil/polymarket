## Суть находки

На Polymarket одновременно торгуются рынки **разной длительности** (5 мин, 15 мин, 1 час, 1 день) с **одним и тем же временем окончания** (`endDate`). У каждого рынка своя начальная цена (`priceToBeat`), зафиксированная в момент старта. Поскольку старт разный, а финальная цена одна — **между рынками существует математическое ограничение на вероятности**, которое рынок иногда нарушает.

### Какие рынки существуют

| Длительность | Recurrence | Окончание | Частота |
|---|---|---|---|
| 5 минут | `5m` | каждые 5 мин (:00, :05, :10, ..., :55) | 12/час |
| 15 минут | `15m` | каждые 15 мин (:00, :15, :30, :45) | 4/час |
| 1 час | `hourly` | каждый час (:00) | 1/час |
| 1 день | `daily` | 1 раз/день | редко |

### Точки пересечения (overlap)

В момент окончания одного рынка могут одновременно заканчиваться несколько:

| Минута | Какие рынки пересекаются | Возможных пар |
|---|---|---|
| **:00** | 5m + 15m + hourly (+ daily) | **3 пары** (5m↔15m, 5m↔1h, 15m↔1h) |
| :05 | только 5m | 0 |
| :10 | только 5m | 0 |
| **:15** | 5m + 15m | **1 пара** |
| :20 | только 5m | 0 |
| :25 | только 5m | 0 |
| **:30** | 5m + 15m | **1 пара** |
| :35 | только 5m | 0 |
| :40 | только 5m | 0 |
| **:45** | 5m + 15m | **1 пара** |
| :50 | только 5m | 0 |
| :55 | только 5m | 0 |

**Итого: 6 пар/час** (4 × 5m↔15m + 1 × 5m↔hourly + 1 × 15m↔hourly).

### Как устроен отдельный рынок

```
1h рынок:  стартует в :00, заканчивается в :00 (+1ч), priceToBeat = цена BTC в :00
15m рынок: стартует в :00, заканчивается в :15, priceToBeat = цена BTC в :00
5m рынок:  стартует в :10, заканчивается в :15, priceToBeat = цена BTC в :10
```

Все рынки резолвятся по одной и той же финальной цене (Chainlink BTC/USD).

### Три возможных состояния при резолве

Допустим: `priceToBeat_5m = $71,185`, `priceToBeat_15m = $71,220`:

| Финальная цена | 5m Up (>= $71,185) | 15m Up (>= $71,220) |
|---|---|---|
| **>= $71,220** | Up ✅ | Up ✅ |
| **$71,185 — $71,220** | Up ✅ | Down ✅ |
| **< $71,185** | Down ✅ | Down ✅ |

### Фундаментальное ограничение

Поскольку $71,185 < $71,220, условие "цена >= $71,185" **всегда легче** выполнить:

> **P(5m_Up) ≥ P(15m_Up)** — математическая истина

Это значит:
- Цена токена `5m_Up` **должна быть ≥** цены токена `15m_Up`
- Эквивалентно: цена `15m_Down` **должна быть ≥** цены `5m_Down`

## Арбитражная стратегия

### Когда возникает расхождение

Если рынок ошибочно оценивает `hard_Up` (рынок с более высоким порогом) **дороже**, чем `easy_Up` (рынок с более низким порогом), то:

```
hard_Up_bid > easy_Up_ask  →  РАСХОЖДЕНИЕ!
```

### Сделка

1. **Купить** `easy_Up` по ask
2. **Купить** `hard_Down` по ask (= продать `hard_Up` по bid)

```
Стоимость = easy_Up_ask + (1 - hard_Up_bid) = easy_Up_ask + hard_Down_ask
```

### Выплаты при любом исходе

| Исход | easy_Up | hard_Down | Выручка |
|---|---|---|---|
| Цена выше обоих порогов | $1 | $0 | **$1** |
| Цена между порогами (**джекпот**) | $1 | $1 | **$2** |
| Цена ниже обоих порогов | $0 | $1 | **$1** |

**Минимальная выручка = $1.00 при любом исходе.**

Если стоимость < $1.00 → **гарантированная прибыль**.

### Пример (реальный, 23 марта 2026, 18:30 UTC)

```
5m:  priceToBeat = $70,962.42 (easy — ниже порог)
15m: priceToBeat = $70,963.90 (hard — выше порог)
Gap: $1.48

Ордербуки в 18:25:
  easy_Up (5m) ask  = 0.500
  hard_Up (15m) bid = 0.630  ← ДОРОЖЕ! Расхождение!

Сделка:
  Buy 5m_Up   @ 0.500
  Buy 15m_Down @ 0.370  (= 1 - 0.630)
  ─────────────────────
  Стоимость:    $0.870
  Мин. выручка: $1.000
  Гарант. профит: $0.130 (14.9% ROI)

Ликвидность: $122-226 на лучших уровнях
```

## Характеристики расхождений

### Когда возникают

- **Малый gap между priceToBeat** ($0 — $15): рынки не различают "почти одинаковые" страйки
- **Overlap-окно** (последние 5 минут): оба рынка торгуются одновременно
- Расхождения **устойчивые**: держатся минутами (сотни последовательных снэпшотов), а не мелькают на секунду

### Почему рынок не эффективен

1. **Отдельные пулы ликвидности** — 5m и 15m торгуются как независимые рынки
2. **Нет кросс-маркетных маркет-мейкеров** — никто не арбитражит связь между рынками
3. **Разное время старта** — 15m рынок торгуется 10 минут до открытия 5m, цена за это время меняется
4. **Малые объёмы** — на отдельных уровнях $10-$500, что не привлекает институционалов

### Лимитирующие факторы

- **Ликвидность**: основной bottleneck, $7-$500 на ноге
- **Execution risk**: нужно исполнить обе ноги атомарно или очень быстро
- **Комиссии**: см. раздел [Экономика и бюджет](#экономика-и-бюджет)

## Экономика и бюджет

### Комиссии Polymarket (Crypto)

Формула: `fee = C × p × feeRate × (p × (1 − p))^exponent`

Где `C` — кол-во шер, `p` — цена.

| Параметр | Текущие (до 30 марта 2026) | Новые (с 30 марта 2026) |
|---|---|---|
| feeRate | 0.25 | 0.072 |
| exponent | 2 | 1 |
| Maker rebate | 20% | 20% |
| Peak effective rate | **1.56%** (при p=0.50) | **1.80%** (при p=0.50) |

Ключевые значения effective rate:

| Цена | Текущий fee | Новый fee |
|---|---|---|
| 0.10 | 0.20% | 0.65% |
| 0.25 | 0.88% | 1.35% |
| 0.50 | **1.56%** | **1.80%** |
| 0.75 | 0.88% | 1.35% |
| 0.90 | 0.20% | 0.65% |

> **Maker (лимитные ордера) — комиссия 0%.** Только taker платит. Это критично для стратегии.

### P&L с учётом комиссий (данные 23 марта 2026)

| Сценарий исполнения | Текущие fees | Новые fees (с 30 марта) | Профитабельных |

| 1 мейкер + 1 тейкер | **$62/день** | $60/день | 20/20 |
| Оба мейкера (лимитные ордера) | **$69/день** | $69/день | 20/20 |

### Требуемый бюджет

**$200-$350 достаточно.** Причины:

1. **Ликвидность — bottleneck, не капитал.** Все 20 сделок ограничены ликвидностью ($1-$332 на сделку). Даже с бюджетом $10,000 прибыль та же.
2. **Быстрый оборот капитала.** Рынки резолвятся за 5-15 минут → капитал возвращается и используется в следующей сделке.
3. **Максимум 1-2 одновременных сделки.** 20 расхождений за 18 часов = в среднем 1 сделка в 54 минуты.
4. **Макс. капитал в одной сделке:** $332 (BTC 15:15, 204 шеры × $0.96 + $0.96).

### Maker execution — ключ к прибыли

Разница между maker и taker: **$62 vs $50/день** (+24%).

Почему maker реалистичен:
- Расхождения держатся **минутами** (100-688 снэпшотов подряд)
- Достаточно времени поставить лимитный ордер и дождаться fill
- На одной ноге (с меньшей комиссией) ставим маркет-ордер, на другой — лимитный

### Смена комиссий 30 марта 2026

Влияние минимально: **$62 → $60/день** (−3%). Новая формула (exponent=1) чуть дороже при средних ценах, но разница $2/день. Стратегия остаётся профитабельной при любом сценарии.

### Важно: сортировка ордербука

- **Bids**: отсортированы **по возрастанию** (worst → best). Best bid = **последний** элемент
- **Asks**: отсортированы **по убыванию** (worst → best). Best ask = **последний** элемент
- Реальные спреды: **1-3 цента** (не 0.01/0.99!)

## Тройные комбинации (5m + 15m + hourly)

В моменты :00 пересекаются **все три** типа рынков. Это создаёт **три одновременные пары** для проверки:

```
Пример: endDate = 13:00 UTC

hourly: priceToBeat = $70,122 (старт в 12:00, drift за 1 час)
15m:    priceToBeat = $70,750 (старт в 12:45)
5m:     priceToBeat = $70,820 (старт в 12:55)

Пары для проверки:
  1. 5m ↔ 15m    (gap = $70, overlap = 5 мин)
  2. 5m ↔ hourly (gap = $698, overlap = 5 мин)
```

Преимущества тройных точек:
- **Больший gap** у hourly-пар (цена за час двигается сильнее → больше расхождение)
- **Большее overlap-окно** у 15m↔hourly (15 минут vs 5) → больше времени на обнаружение и исполнение
- **Три независимых шанса** на расхождение в одной точке

## Тройные арбитражи (3 ноги): результаты анализа

### Идея

В точках **:00** одновременно заканчиваются 5m + 15m + hourly рынки. Можно купить комбинацию из 3 токенов, покрывая 4 возможных состояния:

```
Состояние 1: all_Up       → finalPrice >= ptb_easy (самый лёгкий)
Состояние 2: easy+mid_Up  → ptb_mid <= finalPrice < ptb_hard
Состояние 3: easy_Up only → ptb_easy <= finalPrice < ptb_mid
Состояние 4: all_Down     → finalPrice < ptb_easy
```

3 стратегии:
- **A**: easy_Up + mid_Down + hard_Down (защита от "всё вверх")
- **B**: easy_Up + mid_Up + hard_Down (ставка на среднее состояние)
- **C**: easy_Up + hard_Down (парная, без средней ноги)

### Результаты

**03-23**: 43 тройных точки проанализированы
**03-24**: 21 тройная точка проанализирована

#### Гарантированный тройной арбитраж: **НЕ НАЙДЕН**

Причина математическая:
- Каждая нога стоит ~$0.35–0.65
- **3 ноги** = $1.05–1.50 суммарно
- Минимальный гарантированный доход (worst-case из 4 состояний) = **$1.00**
- **Guaranteed P&L всегда отрицательный**

Лучшие примеры:

| Дата | Точка | Стратегия | Стоимость | Гарантия | Факт P&L |
|---|---|---|---|---|---|
| 03-23 | BTC 06:00 | A | $1.052 | -$0.052 | зависит от исхода |
| 03-23 | BTC 19:00 | B | $1.41 | -$0.41 | +$1.59 (джекпот) |

#### Почему 3 ноги хуже 2 ног

| Параметр | Парный (2 ноги) | Тройной (3 ноги) |
|---|---|---|
| Стоимость | $0.70–0.95 | $1.05–1.50 |
| Мин. доход | $1.00 | $1.00 |
| Edge | +$0.05–0.30 | **отрицательный** |

Третья нога увеличивает стоимость, но **не увеличивает** минимальный доход — он ограничен $1.00 в любом случае (один токен резолвится в $1, остальные в $0).

### Вывод

Тройные арбитражи — тупик для гарантированной стратегии. Джекпоты (попадание в среднее состояние) дают +$1–2, но это уже ставка, а не арбитраж. **Фокус должен оставаться на парных расхождениях.**

### Вопрос

Имеет ли смысл при поиске арбитража смотреть не только на best bid/ask (уровень 1), но и на 2–5 уровни ордербука? Это увеличит исполняемый размер позиции, но ухудшит среднюю цену (VWAP).

### Методология

Для каждого расхождения (`hard_Up_bid > easy_Up_ask`):
1. Берём top-5 уровней с каждой стороны
2. Считаем кумулятивный VWAP при увеличении глубины 1 → 2 → 3 → 4 → 5
3. Проверяем, сохраняется ли spread (`hard_VWAP > easy_VWAP`) на каждом уровне
4. Считаем исполняемый объём = `min(cum_hard_size, cum_easy_size)`
5. P&L = `(1 - easy_VWAP - (1 - hard_VWAP) - fee) × exec_size`

### Результаты

#### Выживаемость расхождений по глубине

| Глубина | Расхождений выживает | % |
|---------|---------------------|---|
| Depth 1 (best only) | 283 / 283 | 100% |
| Depth 2 | 281 / 283 | 99% |
| Depth 3 | 281 / 283 | 99% |
| Depth 4 | 278 / 283 | 98% |
| Depth 5 | 276 / 283 | **98%** |

**98% расхождений сохраняются до 5-го уровня ордербука.** Это означает, что спред между рынками — устойчивая неэффективность, а не артефакт тонкого стакана.

#### Прирост PnL от использования глубины

| Метрика | Depth 1 only | Depth 1–5 | Прирост |
|---------|-------------|-----------|---------|
| Суммарный PnL (все пары за день) | базовый | +25% | **+25%** |

Источники прироста:
- **Больше исполняемый размер** — главный фактор. На level 1 типичный exec size $100–1,000; на levels 1–5 — $500–10,000
- **VWAP деградирует плавно** — средняя цена ухудшается на ~0.001–0.003 за уровень (при спредах 0.01–0.05 это несущественно)

#### Примеры выигрыша от глубины

| Пара | PnL @ depth 1 | PnL @ depth 5 | Прирост |
|------|---------------|---------------|---------|
| ETH 06:00 (15m↔5m) | $123 | $2,070 | **+1578%** |
| BTC 16:00 (15m↔5m) | $1,015 | $6,784 | +569% |
| XRP 06:15 (15m↔5m) | $28 | $364 | +1189% |
| SOL 01:30 (15m↔5m) | $12 | $183 | +1411% |

Самый большой прирост — в кейсах, где на level 1 мало ликвидности, но уровни 2–5 содержат существенный объём.

#### Случаи, когда глубина вредит

У ~2% пар (7 из 283) расхождение исчезает на уровнях 3–5 (VWAP сходится). Это пары с очень маленьким спредом (0.01). Для них бот должен ограничиться depth 1–2.

### Рекомендации для бота

1. **Считать VWAP по 3–5 уровням** при оценке арбитража, не только best bid/ask
2. **Определять оптимальный размер** по пересечению кумулятивной ликвидности обеих ног
3. **Останавливать набор позиции** когда VWAP-spread падает ниже порога (≤ fee per unit)
4. **Не агрессировать глубже 5 уровней** — за ними спред уже нерентабелен

```
Алгоритм определения размера позиции:

for depth in 1..5:
    hard_vwap = cumulative_vwap(hard_Up_bids, depth)
    easy_vwap = cumulative_vwap(easy_Up_asks, depth)
    spread = hard_vwap - easy_vwap
    if spread <= min_spread_threshold:
        break
    exec_size = min(cum_hard_size, cum_easy_size)

optimal_size = exec_size  // размер, при котором spread ещё рентабелен
```

### @polymarket/cross-market — доменный пакет

#### Почему отдельный пакет?
Логика кросс-маркетного арбитража — это отдельный домен, не связанный с существующей AS-стратегией.
Вынесение в domain-пакет позволяет переиспользовать в бектесте, live-боте и мониторинге.

#### Компоненты

**`FeeCalculator`** — расчёт комиссий Polymarket. Инстанс-методы (не статические) —
модель комиссий передаётся один раз в конструктор, не на каждый вызов.

```typescript
// Формула: fee = round5(size × feeRate × (price × (1-price))^exponent)
const calc = new FeeCalculator(FEE_MODEL_CURRENT); // feeRate=0.072, exponent=1
const fee = calc.takerFee(0.65);
// → 0.65 × 0.072 × (0.65 × 0.35) ≈ 0.01064

// Суммарная fee пары (maker = 0%):
const pairFee = calc.pairFee(0.40, false, 0.55, true);
```

`FEE_MODEL_MARCH30` — исторический alias, сейчас идентичен `FEE_MODEL_CURRENT` (см.
"Смена комиссий 30 марта 2026" ниже про то, откуда взялись текущие rate/exponent).

**`DepthAnalyzer`** — VWAP анализ по глубине ордербука. Тоже инстанс-методы — принимает
`FeeCalculator` в конструктор (комиссия считается на каждом уровне глубины).

```typescript
const analyzer = new DepthAnalyzer(calc);
const levels = analyzer.analyze(hardUpBids, easyUpAsks, { maxDepth: 5, easyIsTaker: true, hardIsMaker: true });
// → DepthLevel[] с cumVwap, execSize, totalPnl на каждом уровне

const optimal = analyzer.findOptimal(levels);
// → уровень с максимальным totalPnl
```

Алгоритм:
1. На каждом depth (1..maxDepth) считаем кумулятивный VWAP для обеих ног
2. `spread = hardVwap - (1 - easyVwap)` (инвертируем easy сторону)
3. `execSize = min(cumHardSize, cumEasySize)`
4. `pnlPerUnit = spread - fees`
5. Останавливаемся когда spread ≤ 0

**`MarketPairMatcher`** — матчинг рынков в пары.

```typescript
// Парсинг тикера: btc-updown-15m-1774231200 → {asset: BTC, recurrence: 15m, endEpoch}
const info = MarketPairMatcher.parseTicker('btc-updown-15m-1774231200');

// Группировка и матчинг:
const matcher = new MarketPairMatcher();
const pairs = matcher.findPairs(markets);
// → MarketPair[] { easy (длинная длительность), hard (короткая), pairType: '5m-15m' }
```

Правила матчинга:
- Группировка по (asset, endDate)
- Easy = рынок с бОльшим recurrence (длиннее → легче → ниже цена)
- Hard = рынок с меньшим recurrence (короче → сложнее → выше цена)
- Поддержка тройных пересечений: (5m↔15m, 5m↔hourly, 15m↔hourly)

**`DivergenceDetector`** — детекция арбитражных расхождений.

```typescript
const detector = new DivergenceDetector({ maxDepth: 5, feeModel, minSpreadAfterFees: 0.005 });
const signal = detector.detect(easyBook, hardBook, pair, nowMs);
// → ArbitrageSignal | null
```

Алгоритм:
1. Быстрая проверка: `hard_Up_best_bid > easy_Up_best_ask`?
2. Если да → полный depth-анализ через DepthAnalyzer
3. Фильтр: `optimalDepth.pnlPerUnit >= minSpreadAfterFees`
4. Возврат сигнала с оптимальной глубиной и PnL

каждого метода) — в

### CrossMarketBacktestEngine

#### Почему отдельный движок?
Существующий `BacktestEngine` работает с одним файлом и одной стратегией.
Кросс-маркетный бектест требует **синхронного реплея двух файлов** с merge по timestamp.

#### Поток данных

```mermaid
graph TD
    A[SnapshotScanner] -->|scan dir| B[MarketInfo[]]
    B -->|findPairs| C[MarketPair[]]
    C -->|для каждой пары| D[readBookEvents easy]
    C -->|для каждой пары| E[readBookEvents hard]
    D --> F[mergeTimelines]
    E --> F
    F -->|TaggedBookEvent[]| G[replay loop]
    G -->|update easyBook/hardBook| H[DivergenceDetector.detect]
    H -->|ArbitrageSignal?| I[PairResult]
    I --> J[CrossMarketBacktestResult]
```

#### Формат NDJSON снапшотов

```jsonl
{"t":"meta","tokenIds":["abc","def"],"m":{"endDate":"2026-03-23T14:15:00Z","events":[{"ticker":"btc-updown-15m-1774231200"}]}}
{"event_type":"book","timestamp":"1711198500000","bids":[{"price":"0.55","size":"1000"}],"asks":[{"price":"0.60","size":"800"}]}
```
