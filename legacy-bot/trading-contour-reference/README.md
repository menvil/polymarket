## Почему перенесено, а не удалено

Контур был **мёртв**: dependency audit на момент переноса показал ноль
объявленных зависимостей и ноль импортов из живого дерева — ни из приложений,
ни из нового контура (`trading-state`, `account-state`, семантические
адаптеры, шины событий).

Но переписывание не воспроизводит того, что выяснялось в бою: какие проверки
понадобились, в каком порядке, и что случалось при отказе посередине.

## Что здесь НЕВЕРНО

Читая код, держите в голове:

- **`PortfolioService` в версии до `c88f7cc5` считал комиссию неправильно** —
  вычитал её из получаемых шар (`feeInTokens = feeUSDC / price`). Механизма не
  существует: комиссия удерживается деньгами. Исправление и замер — в гайде.
- Архитектура здесь **не образец**. Композиция старого рантайма новому контуру
  не подходит и воспроизводиться не будет — сохранены решения и проверки, а не
  устройство.

## Что из этого ещё может понадобиться

`trade-tape` — единственное, чей аналог в новом контуре неполон. Хранение
сделок покрыто и покрыто лучше: `TradingHotState.publicTrades` — это
`RollingWindow`, generic по ценовому домену, а `TradeTape` сам был тонкой
обёрткой над тем же `RollingWindow`.

Не покрыт **перекос по ленте сделок**: `TradeFlowMetrics` считал buy/sell
объёмы, order-flow imbalance и VWAP по окну. В домене есть `imbalance`, но он
по **стакану** — перекос очередей, а не состоявшихся сделок. Это разные
величины.

Портфелю оттуда не нужно ничего: метрики потока — рыночный сигнал, а VWAP
входа считает сам `Position` по лотам. Понадобится это стратегиям.
