# Workflow для Claude: Документация + Код

При выполнении любых изменений в проекте **обязательно** делай следующее:

## 1. Обновляй TSDoc‑комментарии в коде

Перед каждой функцией/классом/методом добавляй/актуализируй комментарий в формате **TSDoc**.

**Обязательные поля**:

- `@param` — описание каждого аргумента
- `@returns` — что возвращает функция
- `@throws` — какие ошибки могут возникнуть
- `@example` — пример использования (в блоке \`\`\`typescript)
- `@remarks` — общее описание логики, решений, алгоритмов

📌 **Пример правильного комментария:**

```typescript
/**
 * Возвращает данные из кэша или запрашивает их из API.
 *
 * Алгоритм:
 * 1. Проверяем наличие ключа в LRU‑кэше.
 * 2. Если запись устарела (TTL) — удаляем её и делаем новый запрос.
 * 3. Сохраняем результат в кэш с новым TTL.
 *
 * @param key - Ключ для кэша
 * @returns Объект данных или `null`, если данных нет
 * @throws {NetworkError} При проблемах с сетью
 *
 * @example
 * ```typescript
 * const user = await getCachedData('user:123');
 * console.log(user.name); // "Иван"
 * ```
*/
async function getCachedData(key: string): Promise<Data | null> {
  // ... реализация
}
```

## 2. Обновляй Markdown‑файлы в docs/

После изменения кода сразу создавай/редактируй соответствующий .md‑файл в директории docs/.

**Правила:**

- Если меняешь алгоритм (например, LRU‑кэш) — обновляй файл docs/algorithms/lru-cache.md
- Если добавляешь новую фичу — создавай файл в docs/guides/[название-фичи].md
- Всегда добавляй:
  - «Почему это сделано так?» (обоснование решения)
  - Шаги работы алгоритма
  - Пример кода (актуальный!)
  - Диаграммы (если нужно — используй Mermaid)

📌 **Пример раздела в docs/algorithms/lru-cache.md:**

````markdown
## Как работает LRU‑кэш

### Проблема
При частых запросах к БД возникает перегрузка. Нужно кэшировать результаты.

### Решение
Используем **LRU (Least Recently Used)** + **TTL**.

#### Алгоритм шагами
1. При вызове `get(key)`:
   - Проверяем наличие ключа в `Map`.
   - Если запись старше `TTL` — удаляем её и возвращаем `undefined`.
   - Если запись есть — перемещаем её в **конец** `Map` (теперь она «самый свежий» элемент).
2. При вызове `set(key, value)`:
   - Если ключ уже есть — удаляем старую запись (чтобы переместить её в конец).
   - Если размер кэша достиг `maxSize` — удаляем **первый** элемент `Map` (самый старый, неиспользуемый).

#### Пример кода (актуальный!)
```typescript
// src/utils/lru-cache.ts
export class LRUCache<K extends string, V> {
  // ... реализация (должна совпадать с кодом в проекте!)
}
```
````

## 3. Проверяй корректность кода

После всех правок **обязательно** выполни команды проверки:

```bash
npm run build && npm test && npm run lint
```

Где в package.json есть скрипты:

```json
"scripts": {
  "build": "tsc -p tsconfig.build.json",
  "test": "jest",
  "test:coverage": "jest --coverage",
  "lint": "eslint src --ext .ts",
  "typecheck": "tsc --noEmit"
}
```

✅ После этого будет:

- Скомпилирован TypeScript код в dist/
- Запущены все тесты (автоматическое обнаружение + специфичные)
- Проверен код на соответствие стандартам ESLint

## 4. Языковые требования

- Пиши все комментарии в коде, TSDoc‑комментарии и документацию на **русском языке**
- Пиши все выводы в логи на **английском языке**
- Пиши все тексты ошибок на **английском языке**
